# Astron 技术报告核心

> 版本边界：本材料依据历史证据基线 `11c6114f6ec0504628f912ebde9ba53821badb03`；只支持该基线对应的陈述，不构成 ZIP 中 `d32d3ec1bc49a78d0b14aabb6bf0daf79d3f4d88` 快照的运行或测试证据。详见同目录 README。


> 事实来源：`ASTRON_COMPETITION_EVIDENCE_BASELINE_V1`。每节分别标明“基线事实”和“解释”；解释用于说明事实的工程意义，不扩展证据范围。

## 1. Problem Background（问题背景）

**基线事实。** Astron 将问题定义为执行责任：动作是否获准、是否实际发生、中断后有哪些可依赖事实、交付物是否有效，以及谁有权宣布任务结束。模型回答只能说明意图，不能单独证明这些事实。基线实跑覆盖一个受控仓库维护任务。

**解释。** 对会调用工具的 Agent，任务风险不仅来自提议内容，也来自提议如何成为副作用、过程如何留下可复核记录，以及完成状态如何成立。这里讨论的是执行治理问题，不代表所有 AI 系统都不安全。

## 2. Core Insight（核心洞见）

**基线事实。** 系统将模型提议、运行时授权和执行、耐久动作记录、外部事实核对、Verifier 验收分别处理。真实任务中，模型先提出 `PROPOSE_COMPLETE`；之后两项验收条件通过，耐久验收被接受，任务才转为成功。对于已测故障窗口，留存运行时证据支持动作无可信终态时进入 `UNCERTAIN` 并要求核对的恢复语义；原始逐进程输出当前不可逐条复查，不属于成功 Live Proof。

**解释。** 完成应当是可验证的运行时状态转移，而不只是模型的自述。相应地，恢复应围绕动作已发生到哪一步来判断，而不是只恢复对话或计划。主记忆点：**AI 说完成，不等于任务真的完成。**

## 3. System Positioning（系统定位）

**基线事实。** Astron 是面向通用 Tool-Calling Agent 的执行治理运行时。Planner、Skills、Context Manager、Project Memory、RAG Lite 和 Tool Calling 可为提议提供支持，但不自行授予权限。当前比赛路径是受控仓库维护任务。基线没有与某个当代通用 Agent 做公平对照实验。

**解释。** Astron 将关注点放在提议之后的执行责任：由谁授权、怎样记录动作、如何处理不确定结果，以及由谁验收任务。该定位不意味着这些机制为 Astron 独有，也不构成对其他框架的性能比较。

## 4. Three Contributions（三项核心贡献）

以下恰为基线列出的三项核心贡献：

1. **可信执行分离（Trusted Execution Separation）。** **基线事实：** A 级证据限于当前实跑。模型输出进入工具路由后仍是数据；运行时使用可信 principal 与有限操作表，经权限引擎和耐久动作运行时决定是否执行。五个实跑动作各有提议、授权、日志和成功回执，五项权威授权决策均为 `allow`。该次实跑没有拒绝动作，因此不证明拒绝路径。
2. **Verifier 控制完成（Verifier-Controlled Completion）。** **基线事实：** A 级证据限于当前实跑。Completion Authority 复核交付物摘要和声明的验收结果，再将结论写入耐久存储。实跑两项验收条件均通过，顺序为 `PROPOSE_COMPLETE`、验证开始、接受、`TASK_SUCCEEDED`。
3. **面向动作事实的恢复（Action-Aware Recovery）。** **基线事实：** B 级证据限于已测故障窗口。执行前先持久化 `ATTEMPT_STARTED`；没有终态的尝试标记为 `UNCERTAIN`。可信核对决定后续状态；`NO_EVIDENCE` 不产生重试资格。恢复主张由独立的确定性故障证据支持，成功实跑没有发生崩溃或重启。

**解释。** 三项贡献分别聚焦于动作能否发生、任务何时算完成，以及中断后如何据动作事实恢复。它们不外推为任意外部系统中的 exactly-once 或全面安全保证。

## 5. Architecture（架构）

**基线事实。** 动作提议经 ToolRouter 进入受限工具运行时；运行时另行提供可信 principal，并由 Permission Engine 决定授权。授权回放记录与 Action Journal 保存授权、尝试及结果。执行结果或 `UNCERTAIN` 状态进入核对和恢复流程；交付物由 Verifier 按声明条件复核，接受后才发生耐久任务完成转移。Checkpoint 不能替代动作日志；计划、记忆和检索文本不提升权限。

```text
用户约束 → Agent / 模型 → 动作提议 → ToolRouter → 受限工具运行时
                                          ↓
                              可信 principal / Permission Engine
                                          ↓
                              授权回放 / Action Journal
                                          ↓
                         ATTEMPT_STARTED → 执行 → 结果 / UNCERTAIN
                                          ↓
                                    核对与恢复
                                          ↓
                             交付物 → Verifier
                                          ↓
                        ACCEPTED → 耐久 TASK_COMPLETED
```

**解释。** 该结构把建议、授权、尝试事实、结果核对和验收拆成不同权威环节，使审查者能分别检查各环节的证据。

## 6. Real-Model Evidence（真实模型证据）

**基线事实。** `ASTRON_REAL_MODEL_END_TO_END_PROOF_V1` 是一次真实模型驱动的受控仓库任务。保存的启动命令证明请求配置为 `openai_compatible` 和 `deepseek-flash`；Provider 返回的 model 字段未记录，因此服务端实际模型名称未知。任务将 `src/limiter.py` 的 `MAX_RPS` 从 `10` 改为 `20`，保留另两个常量，并写出 `.astron-artifacts/limiter-report.json`。结果为五次 Provider 调用、五次模型决策、五次提议和执行、五次授权、零次拒绝。应用记录和执行前后工作区快照观察到零禁止变更及零越界写入；这不是操作系统级完整写入审计。

交付物大小为 128 字节，重算 SHA-256 与耐久记录相同：`3c0a0c51248b9f9431bc869d8e6776b8ce882d0479ae9dba33eb4e258652c173`。`AC-CeilingRaised` 与 `AC-ReportDelivered` 均通过，耐久验收为 `ACCEPTED`，任务为 `SUCCEEDED`。结果归档摘要清单的 22 个成员均经重算匹配。整理本身新增 Provider 调用、产品运行和测试运行均为 0。

**解释。** 这组 A 级证据支持当前受控任务的一条完整正向执行链。一次运行不构成统计可靠性样本；运行中没有故障，因此不支持“该成功实跑演示了恢复”的说法。

## 7. Recovery / Reliability Design（恢复与可靠性设计）

**基线事实。** 恢复证据为独立的 B 级运行时与故障窗口测试证据，支持已测故障窗口中的面向动作恢复语义。真实子进程测试覆盖副作用前、发生副作用后但终态未持久化、终态成功后及终态失败后退出；留存固定故障矩阵摘要为 `15/15`。对应的原始进程输出目录目前不在本机，本次审查不能逐条复查或重放原始输出，也不能将其称为当前提交的回归收据。无可信终态的尝试进入 `UNCERTAIN`；`NO_EVIDENCE` 不产生重试资格。只有可信 `CONFIRMED_NOT_APPLIED` 可进入 `RETRY_ELIGIBLE`，且之后仍需显式调用。已确认成功时核对为终态成功，不重复执行。恢复并非本次真实模型成功实跑的一部分。

**解释。** 该设计针对已测试故障窗口采取保守恢复策略；可公开表述为“恢复能力由留存的故障矩阵摘要和运行时测试支持，范围限于已测故障窗口”。原始逐进程输出目前不可复查。证据不覆盖任意外部服务，不能据此宣称任意系统 exactly-once 或生产规模可靠性已经得到证明。留存回归日志显示曾有 `1608 passed, 2 skipped`，但本次未重跑，且未绑定当前提交哈希；这是留存测试证据，不是当前提交的新鲜全量测试收据。

## 8. Limitations（局限）

**基线事实。** 完整正向真实模型证明只有一个受控任务；Provider 回报的模型标识未持久化；没有通用 Tool-Calling Agent 公平对照；未在成功实跑中触发故障恢复；没有生产规模性能或广泛外部用户复现证据；本次未重跑测试。Agent 事件投影对授权决策过度脱敏，审计需查看权威动作日志和授权回放表。零越界写入的观察范围仅限应用记录及执行前后工作区快照。故障演示材料没有可直接播放的逐事件轨迹。

**解释。** 当前材料适合陈述具体受控任务及已测故障窗口，不能支持行业首创、绝对安全、生产就绪、优于特定框架、统计可靠性或对所有模型普遍适用等结论。
